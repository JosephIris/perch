# Perch for iPhone (ios/)

A companion app: on the same wifi as a computer running Perch (or anywhere,
when the computer and the phone are both on Tailscale), it lists that Perch's
sessions, lets the owner talk into any of them, and reads Claude's answers
aloud. Perch's side already exists and is tested; this folder is the phone's
side.

- Protocol: `docs/PHONE-API.md`. Perch's side: `src/Perch.Core/PhoneServer.cs`
  and `AppController.Phone.cs`. If the app needs something the API lacks, add
  it on Perch's side too (both hosts share Core, so one change covers Windows
  and mac), update the doc, and add a test to `PhoneServerTests`.
- `PerchRemote/PerchAPI.swift` (pairing link, client, models) was written on
  Windows ahead of the project and never compiled. Fix what the compiler
  finds; keep the shapes, they match the server.

## The rules from the root CLAUDE.md that do NOT apply here

The root CLAUDE.md is the desktop app's constitution ("Polished Fluent",
tokens.css, Segoe/Inter, WPF-UI). None of its UI rules apply to this app.
This is an iPhone app and should feel like one: SwiftUI, system fonts, SF
Symbols, standard navigation, Dynamic Type, light and dark. The delivery-gate
and "build both hosts" rules still apply to any change under `src/`.

## Stack

- SwiftUI, iOS 17+, no third-party dependencies.
- Project generated by XcodeGen from `project.yml` (`brew install xcodegen`,
  then `xcodegen generate` in `ios/`). The `.xcodeproj` is not committed.
- Speech to text ON THE PHONE: `SFSpeechRecognizer` with
  `requiresOnDeviceRecognition = true` when supported. Send text, not audio.
- Read aloud: `AVSpeechSynthesizer`. Strip markdown (code fences, `**`, links,
  headings) before speaking; skip code blocks entirely ("code block skipped").
- Pairing token in the Keychain, not UserDefaults.
- QR scanning: `AVCaptureMetadataOutput` (or VisionKit's `DataScannerViewController`).
  Also handle the `perch://pair?...` URL via `.onOpenURL`, so a code scanned
  with the Camera app opens the app paired.

## v1 scope

1. **Pair**: first launch shows a scanner. Parse with `Pairing(url:)`, call
   `connect()`, store it. "Not paired" (401) anywhere sends the user back here.
2. **Sessions**: a list grouped by project, each row the title, a state badge
   (working / done / waiting on you / needs approval / idle) and a sleeping
   marker. Poll `sessions()` every 2–3 s while in the foreground; stop in the
   background. Codex and shell tabs are shown but dimmed (`canSend == false`).
3. **Talk**: open a session, then a big hold-to-talk button. Live transcript
   while holding; on release send with `voice: true`. A tap instead of a hold
   stays listening until a short pause, then sends. A text field for typing too.
4. **Hear**: when a session you sent to goes `working` → `done`, fetch
   `reply(for:)` and read it aloud (a per-session speaker toggle, default on for
   the session you just talked to). Show the reply text on screen as well.
5. **Errors** in plain words: can't reach the computer (not on the same wifi,
   and Tailscale off on the phone or the computer) / phone link off in Perch
   Settings / pairing replaced, scan again / wait a minute.
6. **More than one computer**: the owner has a Windows PC and a Mac, both
   running Perch. Store a list of pairings (scanning a second code adds, it
   doesn't replace) and let the session list switch between computers or
   show both.

Away from home works through Tailscale with no extra code: Perch lists its
Tailscale address in the pairing and `connect()` tries every address at once.
Save the pairing after `connect()`, since it picks up the current address list.

Not in v1: push notifications, approving permission prompts, a live terminal
view.

## Testing without the phone

Perch.Mac runs the same phone server. Build and run it (`dotnet run --project
src/Perch.Mac`), turn on Settings → Phone, and point the Simulator at it: the
Simulator shares the Mac's network, so the LAN address in the QR link works.
Paste the `perch://pair?...` link with `xcrun simctl openurl booted '<link>'`
instead of scanning. Then check a line you send lands in a real Claude tab and
its answer comes back.

That check is automated: `node scripts/phone-sim.mjs` starts an isolated
Perch.Mac with the phone link on and a Claude tab, and prints the link; then
`PhoneLinkUITests` pairs by opening it, types a line into the tab and waits
for Claude's answer on screen (Xcode 27 ships no Simulator window to tap in):

    TEST_RUNNER_PERCH_PAIR_URL='<link>' xcodebuild -project PerchRemote.xcodeproj \
      -scheme PerchRemote -destination 'platform=iOS Simulator,name=iPhone 18 Pro' test

For the device: TestFlight, or a cable plus Developer Mode on the iPhone.
