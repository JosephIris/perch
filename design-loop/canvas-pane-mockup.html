A place to throw everything an agent will need before it starts, so you stop feeding context into a prompt one paste at a time. The drawing surface is the least interesting part. The point is that everything you drop gets resolved into a local, addressable artifact and indexed, so the agent can open any of it on its own.

The resolver is the feature

  

    A whiteboard stores what you dropped. This has to store something an agent can open.
    Those are different jobs, and the second one is where all the value is.

It is attached, not fired

      

        The board belongs to a pane, and the agent is told where it lives. That means you can keep
        throwing things in after it has started. Paste another screenshot mid-task and it is simply
        there the next time the agent looks, with no interruption and no re-prompting. A prompt is
        a moment; a board is a place.
      

    

    

      
Links are relevance, not dependency

      

        Connecting the screenshot to the file it came from is worth one line in the index
        (login-broken.png shows session.ts) and saves the agent a guess.
        That is all an arrow needs to mean here. Proximity and grouping carry the rest, and nothing
        breaks if you never draw one.
      

    

    

      
Collecting is the slow part

      

        The reason a first prompt takes ten minutes is not typing, it is gathering: find the file,
        crop the screenshot, dig up the doc link, copy the trace. Those are all one paste each into
        a board, done as you find them, in any order, without composing a sentence around any of it.
      

    

    

      
It survives the session

      

        The board is a folder in the repo. Come back tomorrow, or hand the task to a different
        agent, or to a person, and the context is still assembled. Right now that context lives in a
        scrollback buffer and dies with it.
      

    

  


  
Worth deciding early

  
    
    
  • Whether fetched links are pinned or refreshed. A cached copy is reproducible and offline; a stale one quietly misleads. Probably cache with the fetch date in the index and a manual refresh.
    • 
    
  • How the agent is told. A line appended to its first prompt is the cheap version. A file it is instructed to re-read is the version that makes mid-task additions work.
    • 
    
  • Whether boards are per-task or per-pane. Per-task is truer to how you would use it, but then boards need their own place in the sidebar rather than riding along with a pane.
