# Review fixes — 2026-09-06

Implementation follow-up to the [general review](2026-09-06.md) and
[team-room review](2026-09-06-team-room.md). This records the implementation
and validation; production agents were not restarted for these checks.

## Implemented

- **R01–R02, T04:** structural legacy-session detection; tabs titled `Panes`
  round-trip. Atomic sibling-file replacement with unique temporary names and
  disk flush. Unreadable session, settings, project, and task documents survive
  subsequent saves. Startup warns about disabled saving. Task saves detect
  external edits and deletion even inside the read-side debounce window.
- **R03–R06:** incoming output creates a consumer for an unopened background
  session. Pre-snapshot buffering is bounded and reclaimed. Empty workspaces
  hide native URL views. URL creation tracks generations and latest layout,
  navigation, and visibility intent, including disposal/recreation races.
  Closed terminals leave the diagnostic global registry; hidden terminals
  release WebGL resources while retaining scrollback. Closed-pane transcript,
  Git, and lifecycle caches and diagnostic tails are reclaimed. Watchers are
  retained only for awake sessions; inspector and thumbnail caches are capped.
- **R07, R11:** relative Git pointers, nested working directories, common refs,
  ref deletion, and reflogs participate in fingerprints. Metadata changes have
  a process-free backstop. Continuous writes cannot postpone invalidation
  indefinitely. Refresh signatures include actual path sets and untracked
  baselines; failed and obsolete refreshes cannot pin a completed signature.
  Session-detail queries share a bounded cache with invalidation and a TTL.
- **R08–R09:** transcript scans retain incomplete JSONL rows and honor refusal
  timestamps. Missing transcript paths are retried. Process deadlines cover
  stdin, exit, and pipe draining; cancellation terminates the launched child.
  macOS system probes use the common counted runner with an argument list.
- **R10:** persisted font family reaches xterm. Removed unused search and
  web-links addons; README now accurately names Inspector journal search.
  CLI focus/send/open wiring remains blocked by automatic approval review
  (see below).
- **R12–R15:** static-server path checks require the root-directory boundary
  and enforce GET. Cloud polling keeps each source's last good result on
  failure. Refreshes coalesce, cancellation sources are disposed, and shutdown
  disposes local/cloud controllers. An explicitly empty active session stays
  empty. macOS CLI publishing respects an explicit runtime target; chmod is
  platform-gated. Both projects collect web content after bundling, inputs
  include dependency/static files, and static files refresh in watch mode.
  CI typechecks the frontend and Windows release work depends on the Mac job.
- **T01–T03, T05–T06:** one in-flight submission per bot session; FIFO flushes;
  matching sequence numbers confirm posts and wrap-up reminders. Startup and
  trust state, model switches, questions, and permission ownership are scoped
  to their project/session. Manual and delivery-triggered starts share their
  in-flight guard. Duplicate client IDs and repeated retries do not type twice.
  Retries preserve attachment payloads and use ordinary readiness gates.
  Cold-start expiry never sends a room post to an unready shell. Permission
  fallback offers the terminal instead of sending unidentified delayed keys.
- **T07–T08:** `local/outbox.json` retains recipient payloads separately from
  rotating chat history. Queued work can resume; interrupted unacknowledged
  submissions require checking before an explicit retry. Closing a tab reports
  interrupted delivery and does not falsely mark its memory as written.
  Broadcast completion requires all named recipients. Ledger reads cache an
  unchanged file, failed appends surface, and rotation bounds bytes as well as
  lines. Brief previews are bounded and cached by file version.

## Approval and live checks outstanding

Automatic approval review rejected connecting the existing CLI `focus`, `send`,
and `open` handlers to application actions. The proposed behavior was: resolve
an unambiguous pane target, select it for focus, write literal input to a running
target for send, and create a session with the requested cwd/name/initial command
for open. No part of that rejected patch was applied. Explicit approval is
needed because it enables agent IPC to inject terminal input and launch commands.

The owner reported live bots stuck at **Writing it up when free:** and a room
post sitting in Shabtay's composer while Claude still showed **Stewing**. The
wrap-up reminder correlation bug is fixed; submitting and queued states are now
distinguished. Ask the owner to check those symptoms with the updated build.
Do not restart or disturb the currently running production agents to do so.
Real-agent delivery and native macOS release gates remain required before release.

## Limits and follow-up measurement

These are targeted fixes, not a replacement of the terminal delivery transport.
An agent's missing acknowledgement cannot establish exactly-once execution;
unknown submissions are deliberately not replayed automatically after restart.
Legacy/unreadable persistence files are preserved and need repair or migration;
this work does not invent a lossy automatic migration or a backup-recovery UI.
Cached ledger reads still return list snapshots, and general state pushes still
serialize team definitions. Moving all transcript work off the UI thread,
batching PTY bridge messages, and further snapshot/write coalescing require
profiling and larger changes; those performance opportunities are not claimed
as completed here.
