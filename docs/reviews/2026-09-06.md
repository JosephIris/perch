## Assessment

The [team-room follow-up](2026-09-06-team-room.md) adds five executable
controller/store reproductions and further delivery, permission, and persistence
findings. Read it before changing team orchestration.

The Core/host/web split is a sound basis for continued development. There is
substantial behavioral coverage and useful resource controls already in place.
The largest gaps are **between** those components: delayed native creation,
unopened terminal consumers, global-store recovery, caller-level polling, and
cleanup across multiple lifetimes. Passing helper tests currently miss these.

Prioritize data preservation (R01–R02), then cold-bot output/delivery (R03), then
native pane lifetime (R04–R05). R11 is the clearest measured performance win.
Priorities below are P1 = fix promptly, P2 = planned correctness/resource work,
P3 = maintenance. Findings are open at the reviewed revision.

## Findings

### R01 — P1: A session named `Panes` deletes the session store

**Reproduced.** `SessionStore.Load` identifies legacy data with
`json.Contains("\"Panes\"")`, then deletes the entire file. That string also
occurs as an ordinary JSON value, including a session title or pane name.

Probe: save a current-schema session titled `Panes`, then load it. Actual result:
title `main`, session file absent. A normal restart also saves the seeded default,
making recovery harder. This affects all sessions in the file, not just the
renamed tab.

Source: [`SessionStore.cs:41`](../../src/Perch.Core/SessionStore.cs).
Fix by inspecting the parsed schema/property at its expected structural location;
never delete a user's store as a substring-based migration. Preserve an original
backup and test arbitrary names plus genuine old-schema data.

### R02 — P1: Crash-safe session persistence is promised but not implemented

**Source-confirmed failure path; no actual crash injected.** Session, settings,
and project saves use direct `File.WriteAllText`, truncating the existing file.
A failed/interrupted write can leave invalid JSON. Session load then silently
seeds defaults and AppController saves immediately at startup. Settings/projects
also fall back to empty/default state. Errors are generally swallowed.

Sources: `SessionStore.cs:130`, `Settings.cs:164`, `Project.cs:147`,
`AppController.cs:470`. [`AtomicFile.cs`](../../src/Perch.Core/AtomicFile.cs) already
contains a replacement helper; BoardStore/TeamStore already demonstrate refusing
to overwrite unreadable input.

Use atomic replacement consistently, retain a known-good recovery copy, surface
save failure, and prevent startup from overwriting unreadable data. Serialize a
snapshot on the owning thread; coalesce writes without weakening durability.
If writes become concurrent, replace the helper's fixed `.tmp` name or serialize
per-path writes. A temp rename alone is not a complete backup/recovery strategy.

### R03 — P1: An unopened bot has no terminal output consumer

**Queue behavior reproduced; full real-agent stall inferred from the connected
flow-control code.** Team `EnsureRunning` can spawn a restored bot before its tab
has ever been viewed. Workspace creates stages only for the active session.
For unknown pane IDs, `feed` appends base64 strings to `pendingBytes` without
writing to xterm or acknowledging bytes. At 256 KiB the PTY reader stops until
ACKs arrive. Continued agent output eventually blocks behind that reader.

The probe fed 32 × 8 KiB: **262,144 queued bytes, zero ACKs**. Removing all sessions
left the queue present. The same missing-consumer problem needs consideration
after a browser reload, when existing PTYs outlive the page's stage registry.

Sources: `AppController.cs:379`, `AppController.cs:4765`, `workspace.ts:375`,
`workspace.ts:572`, `pane.ts:435`, `ConPty.cs:63/329`; UnixPty uses the same limits.

Give every running PTY a bounded output consumer independent of tab activation.
Options include a managed/headless terminal consumer or hidden initialized
terminals with controlled rendering. Specify retention and replay semantics;
blindly ACKing an unbounded queue just changes the stall into a memory leak.
Reclaim queues on close and test a cold bot producing well over 256 KiB without
ever selecting its tab, plus renderer recovery with background PTYs.

### R04 — P1: Native URL creation loses intent and confuses generations

**Reproduced against real Core `UrlPanes` with a deferred host factory.**

- Visibility changes during creation are ignored because the pane is not yet
  in `_panes`. Completion creates `DesiredVisible=true`, so a tab switched away
  from during startup can display its native view over the current tab.
- Later layout/URL messages during creation are discarded by `_pending.Add`.
  The old rectangle/URL is used until another post-completion layout arrives.
- `_pending` stores only IDs. Dispose and recreate the same ID before the old
  factory finishes: the old completion sees the new ID as valid, installs its
  old host, and removes the new pending marker. The new completion then closes
  itself. Probe: old host remained open, new host closed, old URL retained.

Sources: [`UrlPanes.cs`](../../src/Perch.Core/UrlPanes.cs):62, 105, 122–138.
Track a per-create generation/object with latest URL, rect, and visibility.
Apply current intent only if the completing request still owns that generation.
Test suppression, close/reopen, failed creation, and CloseAll/recreate races.

### R05 — P2: Empty workspace skips hiding native URL panes

**Workspace method reproduced; native visual effect inferred.** In
`Workspace.render`, `!active` sets stage DOM containers to `display:none` and
returns, bypassing `hideStage`. Native views require their own visibility
message; CSS cannot hide them. Sleeping the last active mixed terminal/browser
tab keeps its session in the list, so the stage is retained and takes this path.

Probe: empty workspace set the DOM to `none` but issued zero native visibility
calls. Sources: `workspace.ts:179/240`, `AppController.cs:2575` (sleep path).
Hide/deactivate all stages in the empty-state branch. Verify the actual native
view disappears, rather than only asserting DOM visibility.

### R06 — P2: Sleeping/closing does not reclaim all associated resources

**Retention paths confirmed; total memory impact not profiled.** Workspace's
live set includes dormant sessions, so sleeping keeps the xterm, its 10,000-line
scrollback, addons, and hidden stage. This preserves history, but means the idle
reaper's PTY savings are not equivalent to reclaiming a tab's renderer resources.

Additional owners have no close-time eviction: RepoWatchers keeps every cwd
until app shutdown; transcript readers are forgotten on agent-session changes
but not generally on pane close; Inspector event/thumbnail maps have no bounded
eviction; several AppController pane-keyed caches similarly outlive removed panes.
PaneManager's diagnostic `_tails` are not removed by `Destroy` (test IPC only).

Sources: `workspace.ts:166`, `pane.ts:204/394`, `RepoWatcher.cs:104–130`,
`inspector.ts` cache/thumbnail maps, `AppController.cs:1780/1789`,
`PaneManager.cs:147/225`.

Define a single close/sleep cleanup contract and separate small persistent state
from expensive live resources. Release GPU addons for hidden/dormant terminals,
bound history/image caches, prune pane IDs, and release unused watchers. If
scrollback must survive sleeping, snapshot/restore it deliberately. Validate
100+ create/inspect/sleep/close cycles and compare retained objects, watcher
counts, handles, private bytes, and GPU contexts against a baseline.

### R07 — P2: Git refresh signatures miss real changes and can retain stale results

**Fingerprint gaps reproduced; additional refresh races source-confirmed.**

- Fingerprint only examines `<cwd>/.git`; nested cwd returns an empty signature.
- Linked-worktree fingerprints omit the common Git directory's refs and
  packed-refs. Updating a common remote ref left the fingerprint unchanged in
  the synthetic fixture. Relative gitdir pointers also are not resolved against
  the worktree directory.
- RepoWatcher discards `.git` events but no dedicated Git-metadata watcher
  replaces them. Fingerprints detect changes only when another caller refreshes.
- AppController caches the signature before queries succeed. Its outer gate
  has no TTL, so the lower-level status cache's five-minute TTL cannot recover
  a skipped refresh. Completion checks baseline identity, not cwd or request
  generation; older same-baseline results can overwrite a newer refresh.

Sources: `GitProc.cs:74/129`, `RepoWatcher.cs:69`,
`AppController.cs:2345–2382`. Resolve/canonicalize worktree root, gitdir, and
commondir once; keep cwd-relative path accounting explicit. Watch metadata too,
cache successful results, add bounded retries, and discard stale generations.
Cover nested cwd, linked trees, external fetch/push, failures, and slow overlapping
refreshes. Cache keys need actual relevant inputs, including the untracked
baseline and path sets, not just their counts.

### R08 — P2: Local model limits replay history and drop partial records

**Both reproduced.** ModelLimitWatch advances its byte offset through incomplete
JSONL data, then searches each current chunk for a marker. Split the marker
across two writes and the refusal is permanently missed. Conversely, the first
scan treats any refusal in the tail as happening now, ignoring its timestamp.
A synthetic refusal dated 2020 armed a fresh one-hour hold.

Sources: `ModelLimitWatch.cs:56–96`, caller `AppController.cs:1586`.
This can disable models and trigger team fallback unnecessarily after restart,
or miss a live refusal. Retain incomplete lines as TranscriptReader does; parse
event timestamps and avoid replaying expired observations. Also invalidate a
cached missing transcript location when the file appears after startup.

### R09 — P2: Subprocess timeout and cancellation do not cover the whole operation

**Blocked-stdin behavior reproduced.** ProcRunner installs its timeout only
after `StandardInput.WriteAsync` completes. A child that never reads a large
prompt can block before the timeout exists. A 200 ms configured timeout was
still incomplete after 1,200 ms; the probe then terminated only its own child.
With `timeoutMs=0`, cancellation goes through the outer catch without explicitly
terminating the child. Disposing a Process handle is not process termination.

Sources: `ProcRunner.cs:168–187`. Use a single linked timeout/cancellation scope
from launch through stdin, exit, and pipe draining, with explicit child cleanup.
Also cover descendants retaining redirected pipe handles after the parent exits.

macOS has another instance: `MacSystemProbe.Run` synchronously reads stdout and
stderr before `WaitForExit(5000)`, so that wait does not bound those reads; the
helper also bypasses ProcRunner counting. Route captured subprocesses through a
common implementation where feasible. Native app launches/PTYs need separate
accounting, not an indiscriminate replacement with redirected processes.

### R10 — P2: Addressable CLI verbs are disconnected; search/font paths are dead

**Source-confirmed.** CLI `focus`, `send`, and `open` serialize valid messages.
PerchIpc dispatches `OnFocus`, `OnSend`, and `OnOpen`, but no production code
subscribes to those events. PaneManager wires the other events and omits these.
The one-way client can report successful sending even though no action happens.

Sources: `tools/perch-cli/Program.cs` CmdFocus/CmdSend/CmdOpen,
`PerchIpc.cs:25–27/153–161`, `PaneManager.cs:200–219`.
Either restore routing/target resolution with integration tests or remove the
advertised commands and return an explicit unsupported result.

Other dead surfaces: `@xterm/addon-search` has no production import/loading;
terminal search is advertised in README, but only Inspector journal search is
wired. `@xterm/addon-web-links` is replaced by the custom link provider and remains
an unused dependency. `Settings.FontFamily` is persisted but never consumed by
the page; pane construction hardcodes the bundled font stack. Decide whether to
finish or retire these surfaces. Removing unused dependencies improves install
maintenance; they are not currently inflating the bundle via imports.

### R11 — P2: Inspector bypasses the Git refresh cache

**Measured: 3 unchanged detail requests → 12 Git launches.** The visible
Inspector polls every two seconds while its agent is working. Each host request
calls `SessionDetailAsync` directly, which invokes reflog, log, diff, and (with
an untracked baseline) ls-files. None of this detail work uses the status cache.
This is about active-agent monitoring, not fully idle tabs: its poll stops when
the agent settles.

Sources: `inspector.ts:43/827`, `AppController.cs:3260–3263`,
`GitProc.cs:351–433`, `SpawnBudgetTests.cs`.
For a prompt/model/tool wait with unchanged files, the current two-second cadence
can still cost approximately **two Git launches/second** when requests complete
within the interval. That is a call-count extrapolation, not a live desktop CPU
measurement. Existing status-cache tests do not exercise this caller.

Cache/share GitSessionDetail by validated repository change epoch and attribution
inputs; let the journal advance independently. Return unchanged/versioned data
instead of serializing and rebuilding all rows. Add a budget test for repeated
Inspector requests during unchanged working-agent state, and an invalidation
test proving file changes still appear promptly.

### R12 — P2: macOS static-server root confinement uses an unsafe prefix test

**Source-confirmed boundary error; no HTTP exploit run.** The server decodes the
URL path, canonicalizes it, and accepts `full.StartsWith(_root)`. A sibling such
as `/app/wwwroot-extra/file` shares the `/app/wwwroot` prefix but is outside the
served directory. An encoded traversal surviving URL normalization can reach
that check. This is a loopback read surface, not evidence of remote execution.

Source: `StaticServer.cs:55–60`. Check path-component containment (root plus
separator or a validated relative path), and explicitly handle symlink policy.
Add literal/encoded traversal, sibling-prefix, and symlink fixtures on macOS.
The class also claims GET-only serving but does not enforce the HTTP method.

### R13 — P2: Failed cloud scans can look like successful resource disappearance

**Source-confirmed.** `ListRawAsync` returns null on command failure;
`ParseSafe` converts null/malformed input to an empty resource list;
CloudController installs that as `_last`. If attributed listing fails but GPU
radar succeeds, the same resource can also lose its original ownership treatment.
Users can see resources vanish or change classification while they still exist.

Sources: `CloudPoller.cs:120–139`, `CloudController.cs:107`.
LocalController already distinguishes failed scans from successful empty scans.
Use a result with success/stale/error state for each cloud source, retain the last
good ownership picture, and visibly mark stale data. No live GCP calls were made.

### R14 — P2: Null active-session state means two different things

**Source-confirmed.** SessionStore and the page intentionally support an empty
workspace with sessions still present (e.g. sleeping a tab with no live sibling).
`AppController.ActiveSession()` instead returns the first session when
`ActiveSessionId` is null. In particular, test-control verbs that use the helper
can target an arbitrary hidden/dormant session while the UI says nothing is
selected; `EnsureActivePane` also uses the same fallback.

Sources: `AppController.cs:1154–1158`, `SessionStore.cs` close/PickActiveAfter,
`workspace.ts:179`. Preserve null as no selection; seed a default explicitly only
where that is the intended action. Test commands from the empty workspace with
several dormant and cross-project sessions, not just an empty store.

### R15 — P2/P3: Build and release gates do not fully match project promises

**Windows failure reproduced; other items verified in build files.**

- mac build always invokes `chmod` even on Windows, preventing a complete local
  cross-build. Both mac CLI publish targets hardcode `osx-arm64` despite declaring
  `osx-x64`; x64 is explicitly untested in README. Derive CLI RID from the target
  and gate host-specific staging appropriately.
- Both host content globs are evaluated before a first bundle exists. CI and
  packaging work around this by prebundling; README's bare first build path can
  miss the bundle. Make project content inclusion robust after generation.
- MSBuild bundle inputs omit package files, fonts, and icons, and track only
  app.js as output. Asset/dependency-only changes or a missing app.css can be
  skipped. esbuild watch only copies static assets once.
- CI runs web tests and esbuild but no TypeScript check. esbuild does not check
  types; add the existing typecheck command as a gate.
- Windows tag publishing is independent of the mac job (no `needs: mac`). A
  failing mac job does not prevent the Windows job publishing a release. The
  real-agent gates are manual, as documented, not enforced by the workflow.

Sources: both host csproj files, `src/web/esbuild.config.mjs`,
`.github/workflows/build.yml`, `packaging/pack-mac.sh`.
Keep signing/release changes separate from routine review fixes; this audit did
not publish, tag, or change the release workflow.

## Additional resource improvements

| Opportunity | Mechanism and validation |
|---|---|
| Release unused repo watchers | Key by normalized actual root; retain only while consumers need them. Current per-cwd watchers can overlap and include generated dependency trees. Measure event rate and handle count during builds/churn. |
| Bounded watcher debounce | Continuous writes restart the 400 ms timer forever, delaying invalidation until the tree quiets. Add a maximum latency while coalescing bursts; test a continuously writing producer. |
| Incremental Inspector rendering | Tail parsing is incremental, but Collapse/events serialization and rendering still revisit history. Add versions/deltas and list windowing only after profiling long transcripts. |
| Move transcript IO off the state thread | `OnInspectorRequest` calls `InspectorFor` before its first await; model-limit scans also read on that thread. Use snapshots and per-reader serialized ownership, not concurrent access to mutable tail dictionaries. Measure dispatcher stalls on large/missing transcripts. |
| Centralized disposal | AppController.Shutdown does not call LocalController/CloudController.Dispose. Stop/dispose timers, cancel work, reject late callbacks, and unsubscribe bridge events. Async cloud startup also needs a disposed-state check after its availability await. |
| Cancel/coalesce refresh work | Local/cloud refresh cancels previous calls but repeatedly allocates CTS objects without disposal. Local native probes may continue after cancellation. Coalesce when a fresh scan is already in flight and make cancellation/lifetime explicit. |
| Batch persistent state writes | Many metadata/UI actions serialize and write the full store synchronously. After fixing durability, debounce snapshots with a maximum delay and immediate critical flushes. Count writes under hook bursts. |
| Batch PTY bridge messages | One UI dispatch and base64/JSON allocation per PTY read is correct but costly for many producers. Measure before aggregating, and preserve byte-exact ACK accounting, bounded buffers, and low typing latency. |
| Measure the whole app | ProcRunner counts only callers using it. mac native probes and wrapper hook processes need separate instrumentation; status-helper budget tests cannot stand in for aggregate process/CPU/memory measurements. |

Do not remove backpressure, lower scrollback blindly, or increase refresh
intervals to hide errors. R03, R06, R07, and R11 need compatible lifecycle and
cache contracts so a memory improvement does not lose output or leave stale UI.

## Reproduction commands

From the repository root, with existing .NET/web dependencies installed:

```powershell
dotnet run --project docs/reviews/2026-09-06-probes/ReviewProbes.csproj --no-launch-profile
node docs/reviews/2026-09-06-probes/workspace.mjs
```

These are **observation harnesses, not a passing correctness suite**. Exit 0
means execution completed; compare expected and actual values printed per
finding. They are deliberately outside the default test projects. When fixing
a finding, turn the scenario into a normal assertion in the appropriate suite.

The C# harness uses Core's existing friend-assembly access, creates only synthetic
temp data/repositories, and starts one short-lived child that intentionally does
not read stdin. It kills only that child's reported PID and leaves the unique
scratch directory printed in its output for inspection. The workspace harness
executes the real transpiled Workspace methods with inert imports and stage
doubles; it is not a live WebView2, PTY, or agent test.
